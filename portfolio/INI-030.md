## Outcome

The git relay pushes directly to `{{CANONICAL_GITHUB_USER}}/{{REPO_NAME}}` main branch over SSH. No PR creation, no browser merge step, no password prompts. The CEO triggers commits via the drop-file relay; changes land on canonical main automatically. The fork (`{{SYSTEM_USER}}`) stays in sync in the same relay run.

## Problem

The current relay pushes to an `auto/*` branch on the `{{SYSTEM_USER}}` fork over HTTPS. The CEO then manually creates a PR, merges, and pulls — a multi-step browser workflow that adds friction without adding governance value. The President Agent commit gate is the real governance control; GitHub's PR review is redundant overhead.

## Scope

### Phase 1 — SSH key and deploy key (Engineering Director + CEO)

Engineering Director generates an SSH key pair on the Mac mini and stages the public key for the CEO to add as a deploy key.

### Phase 2 — Remote URL migration and relay update (Engineering Director)

Update the governance repo's remote URLs from HTTPS to SSH. Update the relay script to:
- Push directly to `upstream` (`{{CANONICAL_GITHUB_USER}}`) main
- Push to `origin` (`{{SYSTEM_USER}}`) main to keep fork in sync
- Add `git pull --rebase upstream main` before committing to stay current with canonical
- Remove `auto/*` branch creation logic

### Phase 3 — Governance manual update (President Agent)

Update § Source Control Governance in the governance manual to reflect direct-to-main push model. Remove references to PR creation, fork PR workflow, and branch-based commit pattern.

## Dependencies

- CEO must add the Mac mini's SSH public key as a deploy key on `{{CANONICAL_GITHUB_USER}}/{{REPO_NAME}}` (write access) before Phase 2 can proceed. This is a GitHub UI action — Engineering Director stages the key, CEO installs it.

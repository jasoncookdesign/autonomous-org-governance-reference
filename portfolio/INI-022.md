## Outcome

No Cowork session triggers the git relay without explicit CEO approval of the full changeset. The CEO sees a structured summary of every file that will be committed before the branch is created — not after. Merge conflicts and surprise branch proliferation are structurally reduced.

## Scope

**Deliverables:**

1. **Governance Manual amendment** — adds § Commit Authorization under source control governance. Policy: before invoking the relay, the President Agent must present the CEO with a commit summary listing every file to be added, modified, or deleted, the proposed commit message, and any known risks (e.g., conflicts with open PRs). The relay is not triggered until the CEO explicitly approves.

2. **President Agent role update** — adds commit gate responsibility to `roles/president-agent.md`. The President Agent is responsible for drafting the summary and waiting for explicit approval; it does not interpret a general "ready to commit" or "go ahead" as blanket authorization for future commits.

3. **Session handoff note** — adds a standing reminder to the session handoff template: list any open PRs before starting a new commit cycle, so the President Agent can check for conflicts before staging changes.

4. **Post-merge cleanup procedure** — documents the three steps required after every PR merge into canonical main: (a) delete the source branch from the {{SYSTEM_USER}} fork; (b) sync the fork's main with canonical via GitHub's "Sync fork" button; (c) pull local main on the Mac mini (`git fetch upstream && git merge upstream/main`). This procedure applies to all branches — merged and closed/superseded alike.

5. **Superseded branch policy** — when a branch is closed without merging (e.g., replaced by a corrected branch), it must be explicitly deleted from the fork at close time, not left to accumulate.

## Notes

**2026-06-05:** Identified after a branch proliferation incident (two open PRs from the same session, with a conflict caused by insufficient coordination). The commit gate adds one deliberate checkpoint. It does not slow down normal work — it just makes the CEO a conscious participant in what goes to source control, rather than a passive approver after the fact.

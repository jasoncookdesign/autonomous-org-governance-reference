## Outcome

If the Mac mini is destroyed or wiped tomorrow, the organization can be fully reconstructed. The CEO knows which artifacts need to be backed up, where they are backed up, and what the step-by-step rebuild sequence is. Recovery is a documented procedure, not a reconstruction from memory.

## Scope

**Phase A — Inventory (Engineering Director workload):**
Audit every artifact that exists only on SandboxData or the Mac mini local filesystem. Produce a recoverability matrix: what's in GitHub (recoverable), what needs backup infrastructure, what must be recreated from documentation (credentials — never backed up raw).

Known gaps identified already:
- Agent definitions (`{{SANDBOX_DATA_ROOT}}/agents/`) — not in governance repo
- KB vault (`{{SANDBOX_DATA_ROOT}}/knowledge/`) — no offsite copy
- Scheduled task configurations — no export mechanism

**Phase B — Backup infrastructure:**
Propose and implement backup solution for artifacts identified in Phase A. Options to evaluate: add agent definitions to governance repo, GitHub private repo for KB vault, or encrypted offsite export. CEO approves selected approach.

**Phase C — Procedure document:**
`operations/sandbox-rebuild-procedure.md` — step-by-step rebuild sequence, ordered by dependency. Includes: credential rotation steps (not backups), relay re-activation, governance repo re-clone, KB restore.

**Phase D — Operating Charter amendment:**
Add § Business Continuity (draft policy language already exists in governance evaluation document).

## Dependencies

- INI-003 should be complete or in progress — the rebuild procedure references the shutdown procedure (shutdown is step 0 of a controlled rebuild)
- CEO must approve backup infrastructure proposal before Phase B implementation

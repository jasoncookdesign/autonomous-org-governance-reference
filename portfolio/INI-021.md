## Outcome

Initiative ID collisions are structurally prevented. When a Cowork session assigns a new ID, it is guaranteed to be unique against the canonical repo's main branch — not the local fork — so two concurrent sessions can never claim the same number.

## Scope

**Deliverables:**

1. **Governance Manual amendment** — adds § Portfolio ID Assignment under the portfolio governance section. Policy: before assigning any new initiative ID, the President Agent must determine the highest existing ID on `{{CANONICAL_GITHUB_USER}}/{{REPO_NAME}}` main (not the {{SYSTEM_USER}} fork). New IDs increment from that value. Assignment is not reserved until the commit is on a pushed branch.

2. **Procedure note in `portfolio/README.md`** — adds a short "Adding initiatives" section that states the canonical-first rule and links to the governance section.

3. **President Agent role update** — adds the ID reservation check to the President Agent's portfolio management responsibilities in `roles/president-agent.md`.

## Dependencies

- INI-002 should be complete (Governance Manual v1.0 baseline before new sections)

## Notes

**2026-06-05:** Identified after an ID collision between two concurrent Cowork sessions (INI-011 was assigned by two different branches). Root cause: President Agent read portfolio state from local fork main, which was ahead of canonical main. Fix is procedural — no tooling required. The President Agent must fetch or view canonical main before assigning IDs.
